# AI 系统设计

本文档汇总 JPQuiz 中所有 AI 能力的设计方案，包括 AI Tutor 对话、智能组卷、学情点评，以及下一阶段的主动教学升级。

| 能力层 | 当前状态 | 说明 |
|--------|---------|------|
| AI 内容生成 | ✅ 已实现 | 按课次+模块生成学习内容（语法、课文、例句等） |
| AI 智能组卷 | ✅ 已实现 | 目标识别 + 结构化出题 + 本地判题 |

## 二、AI Tutor 对话系统

### 2.1 定位

底部 AI 问答栏的职责：

- 自由问答、知识讲解、学习答疑、解释错题、补充说明
- **不作为正式结构化测验的主入口**（测验在专题页内完成）

### 2.2 Prompt 分层

Tutor 问答统一采用 4 层上下文：

#### Layer 1：Base Safety Prompt

内置、不可编辑、必须始终生效。

- 明确 AI 是《大家的日语》N5 学习助手
- 限制回答范围聚焦日语学习
- 拒绝黄赌毒、政治、宗教、战争、暴力、违法、自残、极端主义等敏感内容
- 阻止借"词汇学习""翻译""例句"名义绕开安全限制

#### Layer 2：Tutor Profile Prompt

账号级可配置（设置页面）。

- 助手名字（默认：`みな先生`）
- 教学风格（`concise` / `structured` / `coach`）
- 输出偏好（`table-first` / `bullet-first` / `mixed`）
- 自定义导师提示词

#### Layer 3：Learner Snapshot Prompt

由系统自动生成，不手写。

- 当前课次与模块
- 当前课掌握度
- 当前薄弱项、最近错题
- 最近测验摘要
- 今日学习时长

这层只传压缩后的结构化学习状态，不传完整原始日志。

#### Layer 4：Task Context Prompt

按问题动态注入。

- 当前课次、当前模块的内容摘要
- 追问时引用当前任务的最近结果
- 只带和本次回答真正相关的教材内容

示例：

- 问"总结第 7 课动词"时，优先带入第 7 课词汇摘要
- 问"再加上中文意思"时，优先延续上一轮任务，而不是重新生成无关结果

## 三、记忆分层

### 3.1 工作记忆

服务"当前任务连续追问"。生命周期短、强相关。

- 当前实现：最近几轮对话 + 当前任务上下文
- 后续升级为结构化任务态（artifact memory）

### 3.2 会话记忆

保留最近多轮问答。

- 只保留最近 `N` 轮，超过阈值后压缩为摘要
- 已落表 `aiConversations`、`aiMessages`、`aiConversationSummaries`

### 3.3 长期记忆

保留稳定偏好与稳定事实。

- 适合沉淀：输出偏好、关注重点、高频薄弱点、学习目标
- 不适合沉淀：一次性闲聊、临时上下文、无法稳定验证的推测
- 已预留 `aiLongTermMemories` 表，后续接入晋升策略

## 四、Token 预算

默认策略："尽量只带必要内容"，而非"尽量多带"。

优先级从高到低：

1. 安全基座（固定短 prompt）
2. 当前任务最相关的课内内容
3. 最近几轮对话（`recentTurns`）
4. 学习者快照（`weakItemsLimit`、`recentWrongAnswersLimit`）
5. 少量长期记忆（`maxLongTermMemoriesPerRequest`）

所有参数通过设置页可调，不写死在代码里。

## 五、配置体系

### 平台级（admin 后台 `/admin/settings`，单例 `admin_model_config` 表）

- AI Provider（OpenRouter / OpenAI / Kimi / DeepSeek / 自定义 OpenAI 兼容端点）
- baseUrl / apiKey / model / wireApi（chat 或 responses）
- 整套配置只在服务端持有，**不下发客户端**；切换 provider 不需要重启

### 用户级（设置页面）

- 助手名字、教学风格、输出格式偏好、自定义导师提示词
- 最近保留轮数、薄弱项数量、最近错题数量
- 总结触发轮数、长期记忆条数
- 上下文 Token 软上限、模块内容摘要条数

### 不可配置

- 基础安全提示词
- 结构化 Quiz JSON 规则
- 目标识别器与组卷器的核心格式约束

原因：安全边界不能依赖用户配置；结构化功能需要稳定格式，不能被随意改坏。

> 注：v1 曾使用「用户自带 API Key（BYOK）+ 客户端加密 localStorage」模式，已下线。理由是用户配置门槛高、key 管理风险大；改为平台统一支付后用户零配置即用。

## 六、AI 智能组卷

### 6.1 组卷来源

| 来源 | 说明 |
|------|------|
| 当前范围随机 | 按当前课次和专题随机生成 |
| 指定目标 | 用户输入词、语法点或句子片段，AI 识别后出题 |
| 错题/薄弱项 | 优先考你之前不会或答错的内容 |
| 混合强化 | 混合当前范围、薄弱项和指定目标组卷 |

### 6.2 目标识别流程

1. 用户输入目标文本（支持中文、日文、假名、语法关键词、句子片段）
2. 系统先做本地匹配（词汇别名 + 标签匹配）
3. 本地匹配失败时调用 AI 识别
4. 页面展示已识别目标，用户确认后再生成题目

### 6.3 出题流程

1. 收集候选知识点池（当前课次 + 当前模块）
2. 构建结构化 prompt，发送给 AI
3. AI 返回标准 JSON（题目、选项、答案、解析、关联知识点）
4. 前端本地判题（选择题索引匹配，填空/翻译文本规范化匹配）
5. 错题与掌握状态同步更新

### 6.4 题型标准

- **选择题**：4 选项单选，本地判题
- **填空题**：单空，AI 提供标准答案 + 可接受答案，文本规范化判题
- **问答题（翻译）**：用户输入完整答案，规则匹配判题（首版不做语义评分）

## 七、AI 学情点评

### 7.1 数据输入

基于系统统计结果（非聊天历史）：

- 各专题掌握度、各知识点掌握状态
- 错题数量与分布
- 测验场次与正确率
- 学习时长

### 7.2 AI 输出

- 当前总体学习状态判断
- 当前薄弱点归纳
- 下一步建议练习方式

## 八、AI 主动教学（下一阶段重点）

### 8.1 设计理念

从「被动工具」升级为「主动教练」。AI 不再只是等用户提问，而是基于学习数据主动干预、引导、抽查。

### 8.2 核心能力

#### 8.2.1 主动欢迎与状态感知

- 识别用户回访，主动打招呼
- 汇报上次学习进展、距离上次学习的间隔
- 提醒待复习内容和薄弱项

#### 8.2.2 持续学习追踪与学生画像

- 持续跟踪：学习进度、答题正确率、错题积累、薄弱词汇
- 形成结构化学生画像，作为 AI 决策的输入
- 画像维度：学习频率、掌握速度、薄弱分布、学习偏好

#### 8.2.3 智能复习抽查

- "标记会了" ≠ 真的会了
- 定期对已标记掌握的内容发起主动抽查
- 抽查结果更新真实掌握度
- 抽查策略：遗忘曲线 + 错题复现 + 关联知识点连带

#### 8.2.4 主动出题与讲解

- AI 根据薄弱点主动出题，不等用户请求
- 发现错误后主动讲解，分析错因
- 在对话中穿插小测验，验证理解

#### 8.2.5 教学策略引擎

根据学生类型调整互动方式：

| 策略 | 适用学生 | 特点 |
|------|---------|------|
| 激进型 | 学得快、追求效率 | 快节奏、高难度、少解释、多挑战、错了直接上难题 |
| 耐心型 | 稳扎稳打、需要鼓励 | 循序渐进、多鼓励、详细讲解、重复巩固、错了温和纠正 |
| 均衡型 | 默认 | 适中节奏、适度讲解、渐进提升 |

- 支持自动识别学生类型（基于学习行为分析）
- 允许用户手动设置/切换策略

#### 8.2.6 陪练计划编排

- AI 制定阶段性学习计划
- 安排每日任务量、复习周期
- 薄弱项强化计划
- 根据执行情况动态调整计划

### 8.3 技术要点

- 增强 AI Tutor 的记忆层：持久化学生画像数据
- 增强决策层：策略引擎根据画像选择互动模式
- 前端入口：对话栏主动推送消息、学习页面嵌入抽查卡片
- 需要定时任务或登录触发来激活主动行为

## 九、数据层设计

### 9.1 现有 AI 相关表

| 表 | 用途 |
|----|------|
| `aiConversations` | 会话元数据 |
| `aiMessages` | 会话消息 |
| `aiConversationSummaries` | 历史对话压缩摘要 |

| 表 | 用途 |
|----|------|

### 9.3 设计原则

- 未来每个账号独立隔离

- 后续上云时可平滑迁移到真正用户体系
